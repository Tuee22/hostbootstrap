# Phase 12 — The step algebra and the single project plan

**Status**: Done
**Depends on**: Phase 5 (installed identity, operator verification, and authority kernels), Phase 7
(Dhall configuration and the generic project model), Phase 8 (ensure reconcilers and the generic Lift),
Phase 9 (lifecycle modes and run leases), Phase 11 (prepared operations)
**Substrates**: linux-cpu
**Gate**: `cabal test all --ghc-options=-Werror` from `core/`

> **Purpose**: Admit a project's authored nodes into one scope-, specification-, plan-, and
> configuration-indexed value whose forward order, topology, stable snapshot, and reverse effects are
> projections of the same validated graph.

## Phase Objective

A project authors one identity-parametric `ProjectSpec cfg tcfg`. Scope finalization joins that static
specification to its exact project codec and service registry and yields
`FinalizedProjectSpec scope specDigest cfg`. The finalized value projects `PlanDraft` nodes from one
validated configuration and one canonical project root. `withProjectPlan` admits the resulting non-empty
draft stream under an exact lifecycle profile and yields a generative
`ProjectPlan scope specDigest planId configId cfg`. Every step presented to an interpreter, every topology
edge, every stable snapshot byte, every frame witness, every planned resource, and every reverse effect is
projected from that value.

The plan identity is local and generative; the persisted plan digest is stable and content-derived. The
public `StablePlanSnapshot` is a non-authorizing byte view, while the hidden kernel retains an indexed
companion for protected persistence. The snapshot boundary joins stable and local identities explicitly
through `BoundPlanSnapshot` and `PlanDigestBinding`. The Open branch of existing-snapshot admission,
recovery-profile opening, and reconstruction retain the one `planId` generated by that admission. A
terminal Production acknowledgment instead yields only its stable close key and generates no plan identity.
The context boundary similarly joins descriptive binary context to the exact plan through the pure
`CurrentFrame` admission. These evidence values make cross-scope, cross-configuration, cross-plan,
cross-digest, and cross-frame composition fail at the type boundary.

## Module Surface

`HostBootstrap.Lifecycle.Plan` is a hidden representation kernel. It owns internal node definitions,
validation, canonical encoding, and the constructors for plan-local evidence. It stays in Cabal's
`other-modules` and imports only lower-level plan vocabulary.

The public surface is split into one pure facade and three evidence leaves:

- `HostBootstrap.ProjectPlan` exposes the opaque plan vocabulary and pure projections.
- `HostBootstrap.ProjectPlan.Construct` owns the scope-finalized specification wrapper and joins profiles,
  roots, validated configuration, and drafts.
- `HostBootstrap.ProjectPlan.Snapshot` joins a plan to the
  [lifecycle-modes-and-run-leases phase](phase-9-lifecycle-modes-and-run-leases.md)'s protected snapshot and
  lease transitions.
- `HostBootstrap.ProjectPlan.Frame` joins a plan to the
  [Dhall-configuration-and-generic-project-model phase](phase-7-dhall-configuration-and-project-model.md)'s
  descriptive binary context.
- `HostBootstrap.Authority.ProjectPlan` joins those pure plan projections to the matching protected snapshot,
  lease, journal, and live frame cursor before invoking the lower one-use reservation kernel.

`HostBootstrap.CLI` retains the static `ProjectSpec cfg tcfg` authoring surface. Its scope-finalization
function passes the static plan builder, static service registry, and scope-correct codec to the lower
finalizer; the lower module therefore does not import `HostBootstrap.CLI`.

The dependency direction is:

```text
HostBootstrap.Lifecycle.Plan
    ↓
HostBootstrap.ProjectPlan
    ↓
HostBootstrap.ProjectPlan.Construct
HostBootstrap.ProjectPlan.Snapshot
HostBootstrap.ProjectPlan.Frame
    ↓
CLI scope finalization / lifecycle journal / Authority
    ↓
HostBootstrap.Authority.ProjectPlan
    ↓
Command / Chain / Reconcile / Teardown / resource consumers
```

The hidden kernel imports neither lifecycle mode, command authority, reconciliation, command dispatch, nor
teardown modules. `HostBootstrap.Lifecycle.Mode` may consume the kernel's private indexed snapshot companion
through its restricted internal import, while the snapshot leaf composes those protected primitives above
both modules. `HostBootstrap.Step`, `HostBootstrap.ProjectPlan`, and the hidden kernel import only Phase 7's
pure `HostBootstrap.Lift.Context` vocabulary. `HostBootstrap.Chain` may consume Phase 8's full generic
`HostBootstrap.Lift`, because it is the lower execution fold; plan-aware descent remains above the public
plan facade.

## Target API

The public vocabulary has hidden constructors; `StablePlanSnapshot` is the deliberate unindexed view:

```haskell
data FinalizedProjectSpec scope specDigest (cfg :: Type -> Type)
data PlanDraft scope specDigest config
data ProjectPlan scope specDigest planId configId (cfg :: Type -> Type)
data PlannedStep scope planId configId config
data DerivedTopology scope planId
data StablePlanSnapshot

data CurrentFrame scope planId frame
data ProjectFrame scope specDigest planId configId frame
data ValidatedContext scope planId frame
data PlanDigestBinding scope specDigest planDigest planId
data BoundPlanSnapshot scope specDigest planDigest planId
data BoundInvocationRecovery scope specDigest planDigest planId brokerGeneration

data PlannedResource scope planId resourceId resource frame
data AcquisitionJournal scope planId brokerGeneration
data LifecycleCursor scope planId frame brokerGeneration verb phase
```

The hidden kernel additionally owns
`IndexedPlanSnapshot scope specDigest planId configId`. `ProjectPlan` retains that companion, and only the
snapshot leaf can consume it. It is absent from the public facade; `StablePlanSnapshot` is its index-erased,
non-authorizing byte projection.

The static project specification remains independent of lifecycle scope and every generative identity.
`HostBootstrap.CLI` passes its static service registry and rank-2 plan builder to the lower component
finalizer; the test-config family remains solely on `ProjectSpec cfg tcfg`. Scope finalization reuses the
service-registry continuation and retains the exact codec, services, and identity-parametric builder in one
wrapper:

```haskell
withFinalizedProjectSpec
  :: ScopeKind
  -> ProjectCodec scope initialDigest cfg
  -> ServiceRegistry cfg
  -> (forall planScope rootId.
        CanonicalProjectRoot planScope rootId
        -> cfg planScope
        -> Either StepPlanError StepPlan)
  -> (forall specDigest.
        FinalizedProjectSpec scope specDigest cfg
        -> result)
  -> result

withHarnessFinalizedProjectSpec
  :: ProjectCfg cfg
  => HarnessConfigAuthority projectId runId
  -> FinalizedProjectSpec
       (Production projectId) productionSpecDigest cfg
  -> (forall harnessSpecDigest.
        FinalizedProjectSpec
          (Harness projectId runId) harnessSpecDigest cfg
        -> result)
  -> result

finalizedProjectCodec
  :: FinalizedProjectSpec scope specDigest cfg
  -> ProjectCodec scope specDigest cfg

finalizedProjectServices
  :: FinalizedProjectSpec scope specDigest cfg
  -> FinalizedServiceRegistry scope specDigest (cfg scope)
```

The finalized wrapper produces a non-empty stream in the exact root, scope, specification, and configuration
admitted by the plan constructor. Because authored fragments may depend on the admitted configuration, this
projection validates the concrete stream and reports an empty or invalid result at that boundary:

```haskell
projectPlanDrafts
  :: FinalizedProjectSpec scope specDigest cfg
  -> CanonicalProjectRoot scope rootId
  -> ValidatedConfig scope specDigest configId (cfg scope)
  -> Either PlanError (NonEmpty (PlanDraft scope specDigest (cfg scope)))
```

Fresh admission consumes all authoritative inputs together and generates the local `planId`:

```haskell
withProjectPlan
  :: LifecycleProfile scope
  -> CanonicalProjectRoot scope rootId
  -> ValidatedConfig scope specDigest configId (cfg scope)
  -> NonEmpty (PlanDraft scope specDigest (cfg scope))
  -> (forall planId.
        ProjectPlan scope specDigest planId configId cfg
        -> a)
  -> Either PlanError a
```

The three pure views come from that exact value:

```haskell
forward
  :: ProjectPlan scope specDigest planId configId cfg
  -> NonEmpty (PlannedStep scope planId configId (cfg scope))

topology
  :: ProjectPlan scope specDigest planId configId cfg
  -> DerivedTopology scope planId

renderSnapshot
  :: ProjectPlan scope specDigest planId configId cfg
  -> StablePlanSnapshot
```

Each opaque planned node also has the narrow pure reverse views needed by the reverse scheduler; the
callback is retained data and is not run by the projection:

```haskell
plannedStepIdentity
  :: PlannedStep scope planId configId config
  -> StepIdentity

plannedStepReversePolicy
  :: PlannedStep scope planId configId config
  -> ReversePolicy

plannedStepReverseRun
  :: PlannedStep scope planId configId config
  -> Maybe (HostConfig -> TeardownAction -> IO TeardownOutcome)
```

The plan facade also owns resource lookup. Reconciliation supplies only the closed resource family and stable
operation key; the plan supplies the generative resource and frame indices:

```haskell
data PlannedResourceKind resource

withPlannedResourceOfKind
  :: ProjectPlan scope specDigest planId configId cfg
  -> PlannedResourceKind resource
  -> OperationKey
  -> (forall resourceId frame.
        PlannedResource scope planId resourceId resource frame
        -> result)
  -> Either PlanError result
```

Plan-owned edge and guest-alias projections are derived through the same facade. A `PlannedStep` exposes only
its own resource and declared dependency prefix, so an action cannot perform whole-plan lookup.

Context admission is a pure check of descriptive data. It checks the declared topology and current-frame term
before generating the frame phantom and jointly yields the plan-local frame, project-frame, and
validated-context evidence so callers cannot select one index independently:

```haskell
withCurrentFrame
  :: ProjectCfg cfg
  => ProjectPlan scope specDigest planId configId cfg
  -> BinaryContext
  -> (forall frame.
        CurrentFrame scope planId frame
        -> ProjectFrame scope specDigest planId configId frame
        -> ValidatedContext scope planId frame
        -> a)
  -> Either FrameError a
```

`CurrentFrame`, `ProjectFrame`, and `ValidatedContext` carry no command, journal, or mutation authority. The
effectful lifecycle opener and command-authority gate consume them later with independent root and lease
evidence.

Fresh persistence runs one serialized protected sequence. It stores, flushes, reads back, and verifies the
private indexed snapshot in one protected entry. After leaving that entry, a separate fresh-only lease
compare-and-swap binds the run-lease record to the resulting digest. The two durable transitions are ordered;
they are not an atomic multi-record transaction. Only completion of the whole sequence yields the matching
evidence package:

```haskell
withPersistedPlanSnapshot
  :: RootInvocationAuthority scope brokerGeneration VerbUp
  -> UnboundRunLease scope brokerGeneration
  -> ProjectPlan scope specDigest planId configId cfg
  -> (forall planDigest.
        VerifiedPlanSnapshot scope specDigest planDigest
        -> BoundPlanSnapshot scope specDigest planDigest planId
        -> PlanDigestBinding scope specDigest planDigest planId
        -> BoundRunLease scope specDigest planDigest brokerGeneration
        -> NormalActiveRecovery
             scope specDigest planDigest planId brokerGeneration
        -> IO a)
  -> IO (Either SnapshotError a)
```

Protected admission of an existing Production invocation starts from only the protected store and installed
project identity. It opens the exact Production mode/root, already-bound lease, and immutable verified
snapshot itself. A terminal acknowledgment receives only its stable close key and generates no local plan.
Only the Open branch generates one local `planId` and yields the fully indexed evidence binding that identity
to the persisted digest and broker generation:

```haskell
withBoundPlanSnapshot
  :: ProtectedStore
  -> InstalledProjectIdentity projectId
  -> (InvocationCloseKey -> IO result)
  -> (forall brokerGeneration specDigest planDigest planId.
        RootInvocationAuthority
          (Production projectId) brokerGeneration VerbUp
        -> ProjectModeLease
             projectId ProductionMode brokerGeneration
        -> BoundRunLease
             (Production projectId) specDigest planDigest brokerGeneration
        -> VerifiedPlanSnapshot
             (Production projectId) specDigest planDigest
        -> BoundPlanSnapshot
             (Production projectId) specDigest planDigest planId
        -> PlanDigestBinding
             (Production projectId) specDigest planDigest planId
        -> BoundInvocationRecovery
             (Production projectId)
             specDigest
             planDigest
             planId
             brokerGeneration
        -> IO result)
  -> IO (Either SnapshotError result)
```

The public `BoundInvocationRecovery` constructor is hidden and its indices are nominal. Its hidden
representation retains the already classified Open revision; the scope-only durable observation used to
reach that branch stays package-private and cannot be passed as plan evidence.

For Production recovery, the bound-invocation evidence opens a profile with its already generated `planId`.
The profile opener consumes the complete indexed Open package and does not quantify another local identity:

```haskell
withRecoveredProductionLifecycleProfile
  :: RootInvocationAuthority
       (Production projectId) brokerGeneration VerbUp
  -> ProjectModeLease projectId ProductionMode brokerGeneration
  -> BoundRunLease
       (Production projectId) specDigest planDigest brokerGeneration
  -> VerifiedPlanSnapshot
       (Production projectId) specDigest planDigest
  -> BoundPlanSnapshot
       (Production projectId) specDigest planDigest planId
  -> PlanDigestBinding
       (Production projectId) specDigest planDigest planId
  -> BoundInvocationRecovery
       (Production projectId) specDigest planDigest planId brokerGeneration
  -> (RecoveredProductionLifecycleProfile
        projectId specDigest planDigest planId brokerGeneration
      -> result)
  -> Either ModeError result
```

Restart finalization safely aligns its independent candidate specification/config brand and regenerates
drafts before reconstruction. The hidden token is issued only after exact recovered-profile/finalized-codec
specification agreement, and the config's retained specification and canonical digest are independently
checked while preserving its `configId` and value:

```haskell
withRecoveredProductionProjectPlanInputs
  :: RecoveredProductionLifecycleProfile
       projectId recoveredSpecDigest planDigest planId brokerGeneration
  -> CanonicalProjectRoot (Production projectId) rootId
  -> FinalizedProjectSpec
       (Production projectId) candidateSpecDigest cfg
  -> ValidatedConfig
       (Production projectId) candidateSpecDigest configId
       (cfg (Production projectId))
  -> (ValidatedConfig
        (Production projectId) recoveredSpecDigest configId
        (cfg (Production projectId))
      -> NonEmpty
           (PlanDraft
              (Production projectId) recoveredSpecDigest
              (cfg (Production projectId)))
      -> a)
  -> Either PlanError a
```

Production recovery then reconstructs only the plan whose canonical root, specification, configuration,
regenerated drafts, verified bytes, digest, and generated local identity agree:

```haskell
withRecoveredProductionProjectPlan
  :: RecoveredProductionLifecycleProfile
       projectId specDigest planDigest planId brokerGeneration
  -> CanonicalProjectRoot (Production projectId) rootId
  -> VerifiedPlanSnapshot
       (Production projectId) specDigest planDigest
  -> BoundPlanSnapshot
       (Production projectId) specDigest planDigest planId
  -> PlanDigestBinding
       (Production projectId) specDigest planDigest planId
  -> ValidatedConfig
       (Production projectId) specDigest configId
       (cfg (Production projectId))
  -> NonEmpty
       (PlanDraft
          (Production projectId) specDigest
          (cfg (Production projectId)))
  -> (ProjectPlan
        (Production projectId) specDigest planId configId cfg
      -> a)
  -> Either PlanError a
```

Before command authority or interpretation, the protected lifecycle substrate opens the acquisition journal
for the exact plan and broker generation, then opens a frame/verb/phase cursor from that journal. Both values
retain `brokerGeneration`, so a cursor cannot be paired with a journal or root authority from another broker:

```haskell
withAcquisitionJournal
  :: RootInvocationAuthority scope brokerGeneration verb
  -> BoundRunLease scope specDigest planDigest brokerGeneration
  -> BoundPlanSnapshot scope specDigest planDigest planId
  -> PlanDigestBinding scope specDigest planDigest planId
  -> ProjectPlan scope specDigest planId configId cfg
  -> (AcquisitionJournal scope planId brokerGeneration -> IO result)
  -> IO (Either LifecycleError result)

withLifecycleCursor
  :: AcquisitionJournal scope planId brokerGeneration
  -> ProjectFrame scope specDigest planId configId frame
  -> ProjectVerb verb
  -> LifecyclePhase phase
  -> (LifecycleCursor scope planId frame brokerGeneration verb phase -> IO result)
  -> IO (Either LifecycleError result)

authorizeRootProject
  :: RootInvocationAuthority scope brokerGeneration verb
  -> ProjectVerb verb
  -> VerifiedPlanSnapshot scope specDigest planDigest
  -> BoundPlanSnapshot scope specDigest planDigest planId
  -> PlanDigestBinding scope specDigest planDigest planId
  -> BoundRunLease scope specDigest planDigest brokerGeneration
  -> ProjectPlan scope specDigest planId configId cfg
  -> AcquisitionJournal scope planId brokerGeneration
  -> LifecycleCursor scope planId frame brokerGeneration verb phase
  -> ValidatedLifecycleContext scope specDigest planId configId frame
  -> IO
       (Either
          AuthorityError
          (CommandAuthority
             scope planId frame brokerGeneration verb phase))
```

Sprint 12.25 originally exposed this reservation foundation as Up-only `authorizeProjectUp` with a separately
supplied `ProjectFrame`/`ValidatedContext`. Sprint 17.8 supersedes that public shape with the root-refined generic
signature above and packages the ordinary root-Up consumer behind Cabal-private `LifecycleEntry`; the atomic
reservation kernel and durable journal/cursor foundation remain Phase 12 ownership. This phase supplies the exact
current-frame evidence and reservation substrate. The
[recursive-lifecycle-command phase](phase-17-recursive-lifecycle-command.md) owns the proof-complete
recursive operator/descent authorization gate, authenticated child admission, and complete forward/reverse
state-machine traversal.
